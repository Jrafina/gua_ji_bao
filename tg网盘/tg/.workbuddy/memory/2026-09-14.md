## v1.9：/rm · /move · /pass 三个新功能 + 重新打包

用户要三件事：① bot 里 `/rm 路径` 删文件/文件夹；② `/move '源' '目标'` 移动；③ 部署后忘记密码要有办法找回。
全部做完，部署包 v1.9 = **204,060 B，md5 `639137a3e6875d84fdc7abef746f8c7a`**。
**但没有部署到服务器**——SSH 密码被拒（见文末）。

### 实现（全在 `server/app.py`，新增 `tools/show_password.py`）

- **路径解析层**：`_norm_path()`（归一化）、`_split_args()`（引号优先切分，兼容中文全角引号，
  路径含空格时可 `"/我的 报告"`）、`_resolve_node(conn, path, want)`（同时认出文件与目录；
  同名时目录优先，`-dir`/`-file` 可强制；根目录返回 `("folder", None)`）。
- **`/rm [-f] [-dir|-file] 路径`** 与 `/rm #编号`：
  - 删文件：直接删；删目录：**先弹「确认删除/取消」inline 按钮**（列出子目录数/文件数/总容量，
    token 10 分钟有效、点一次即失效），`-f` 跳过确认；
  - 刻意**取消了"空目录直接删"的捷径**——"文件夹一律先确认"更好记，也少一次手滑；
  - 根目录永远拒绝；同名文件+目录并存时默认按目录处理并在回复里写明；
  - 顺序固定：① 删 Telegram 消息 → ② 删索引 → ③ 写 journal（`del` / `rmd`）。
- **`/move '源' '目标'`**（别名 `/mv`）：源可为文件或目录；目标留空=根目录；
  目标不存在则**逐级自动创建**（与"发文件时写路径"同规矩，每级写 `mkdir`，回复里列出新建了哪几级）；
  自环检查放在**建目录之前**（否则会先在源目录里造出垃圾目录）；同名目录拒绝而非覆盖。
- **`/pass`**：把网页地址（本机 `hostname -I` 同款 UDP 探测 + `TG_NGINX_PORT`）/账号/密码打回聊天，
  带一个「删掉这条消息」按钮（callback `q` → `deleteMessage`）；`TG_BOT_SHOW_PASS=0` 可关。
- **`delete_messages()` 重写**：改走 `_tg_delete_messages()`，`deleteMessages` 批量（100 条/批）+
  失败退回逐条 `deleteMessage`，并按**每行自己的 `chat_id`** 分组（此前固定用全局 CHAT_ID，
  跨会话收录的文件删不掉）。网页端 `delete_folder`/`delete_file` 的 SELECT 也补了 `chat_id`。
- `HELP_TEXT` / `_reply_ls` 页脚 / `deploy.sh summary` 都加了新命令与找回密码的提示。

### `tools/show_password.py`（纯标准库，后端了也能跑）

`--token` 附带 bot token（灾备要重建时用）、`--json`、`--reset --yes` 换新密码（**先备份成

### 测试抓到的真 bug（值得记住的教训）

`/move` 移动**文件**时，我把文件全路径写进了 journal 的 `mv` 事件：
`{"t":"mv","id":..,"path":"/归档区/带空格 文件.txt"}`。
但 journal 约定 `path` 是**所在目录**（`rebuild_index.replay` 直接 `_path = norm(path)`，
`materialize` 拿它当 `folder_id` 找父目录）→ 重放时把文件名当成了目录名，
重放出 `/带空格 文件.txt` 和 `/归档区2/归档区/带空格 文件.txt` 两个假目录。
**这类错误本地不报错、线上也看不出来，只有"重放结果 == 现库"的断言能抓住**——这个断言必须留着。
